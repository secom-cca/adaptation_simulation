# River Basin Adaptation Game（frontend-new）に関するソフトウェア説明

Environmental Modelling & Software への投稿を想定した、アプリケーションの丁寧な記述稿である。本稿はソフトウェアの目的、モデル構造、実装アーキテクチャ、利用者の意思決定フロー、評価指標、教育・参加型利用の位置づけ、利用可能性および限界を、段落形式で整理する。

---

## 1. ソフトウェアの概要と開発動機

River Basin Adaptation Game（以下、本ソフトウェア）は、気候変動下における流域スケールの適応政策を、参加者が段階的に選択・評価できる対話型シミュレーション環境である。`frontend-new` は、その利用者向けインタフェース層として実装された Web アプリケーションであり、バックエンドに配置された年次物理・社会経済シミュレータと連携して、2026年から2100年までの約75年間を三つの意思決定サイクル（おおむね25年ごと）に分割した順次意思決定ゲームを提供する。本ソフトウェアの中心的なねらいは、洪水リスク管理、農業生産性の維持、生態系の保全という複数の目的が同時に存在する流域適応問題を、専門家以外にも操作可能な形で可視化し、政策間のトレードオフ、時間遅れ、予算制約、気候シナリオ依存性を体験的に理解させることにある。

環境モデリング分野では、数値モデルそのものの精緻化と並んで、モデルの結果を政策学習やステークホルダー対話に接続するソフトウェア設計が重要性を増している。本ソフトウェアは、従来の一括型シナリオ比較ツールに加え、参加者が「上流対策」「下流対策」「流域一体対策」といった役割に応じて利用可能な政策集合を変えながら、将来状態を逐次更新していく設計を採用している。これにより、静的な感度分析だけでは把握しにくい経路依存性（path dependence）、ロックイン、短期対策と長期対策の非対称性を、画面上のイベント提示やスコア変化として明示できる。また、ワークショップやオープンラボなどの集合場面での利用を想定し、日本語・英語の切替、直感的な政策スライダー、結果のレーダーチャート比較、他グループ結果とのランキング表示といった機能を備えている。

本ソフトウェアが扱う問題設定は、気候変動に伴う気温上昇と極端降水の変化のもとで、流域の治水、土地利用、農業、生態系、住宅立地が相互に影響し合う系である。対策には、植林・森林保全、堤防・河川改修、田んぼダム、住宅移転、防災訓練、農業研究開発などが含まれ、それぞれ効果の発現時期、費用、累積上限、副作用が異なる。参加者は限られた政策ポイントを毎ターン配分し、その結果として洪水被害額、農作物収量、生態系指標が変化する様子を確認する。最終局面では、対策なしのベースラインや、あらかじめ用意された AI エージェント最適解、さらに同セッション内の他参加者結果と比較できるため、個人の直感的判断を相対化し、集団学習を促す仕組みとなっている。

## 2. ソフトウェアの位置づけと利用可能性

本ソフトウェアは、リポジトリ内で `frontend-new` として管理されるフロントエンドと、`backend` 配下の FastAPI サーバおよび年次シミュレーションモジュールから構成されるクライアント・サーバ型アプリケーションである。フロントエンドは Vite と React により実装され、開発時にはローカルの開発サーバから API プロキシ経由でバックエンドに接続する。バックエンドは `simulate` エンドポイントを中心に、順次意思決定モードでの年次更新、比較結果の保存・取得、大規模言語モデルを用いたフィードバック生成や住民ペルソナ対話などの拡張機能を提供する。シミュレーション本体に関わる乱数は固定シードにより再現可能とする一方、生成 AI による住民ペルソナの属性選択など一部の表現層には意図的なランダム性を残しており、同一政策でも文言レベルの多様性が得られるように設計されている。

典型的な起動手順は、まずバックエンドを起動し、続いて `frontend-new` で依存関係をインストールしたうえで開発サーバを起動するという二系統の起動である。利用者はブラウザ上でユーザ名、任意のチーム名、プレイモード、RCP 気候シナリオを選択してセッションを開始する。本ソフトウェアは研究用の対話型実験環境および教育用デモとしての利用を想定しており、ワークショップでの短期利用、講義でのデモンストレーション、適応政策の探索的学習に適する。ソフトウェアの記述対象を `frontend-new` に置く場合でも、その科学的内容の多くはバックエンドの流域シミュレーションモデルに依存するため、本稿では両者を一体のアプリケーションとして説明する。

## 3. 概念モデルとシミュレーションの枠組み

本ソフトウェアの背後にあるモデルは、流域の気候外力、水循環・洪水過程、農業生産、生態系状態、住宅立地・住民能力、公共投資の累積効果を、年次の状態遷移として表現する。各年において、気温や降水などの気候変数が RCP に応じたトレンドと不確実性のもとで更新され、極端降水の頻度・強度の変化が洪水負荷に反映される。洪水被害は、外力と防御水準（堤防水準、森林による保水、田んぼダムによる一時貯留、住民の防災能力など）および暴露量（高リスク住宅数など）の関係から評価され、農業収量は気温条件、高温耐性、水利用、洪水による二次影響などを通じて計算される。生態系指標は、森林面積、治水インフラ、水質・水量関連の代理変数などと結びつき、構造物対策の強化が生態系へ与える副作用も表現可能な設計になっている。

政策入力は、利用者には 0 から 10 の整数的な政策ポイントとして提示されるが、バックエンド内部では年間予算換算ルールに基づき、植林本数、移転戸数、堤防投資、田んぼダム投資、防災訓練強度、農業 R&D 投資といったモデル単位へ変換される。政策には最小実施単位、1 ターンあたりの上限、累積上限が設定されており、例えば堤防・河川改修は一定ポイント未満では事業化されないこと、田んぼダムや防災訓練・農業 R&D にはターン上限があること、住宅移転には累積上限があることなどが UI とモデルの双方で一貫して扱われる。また、政策ポイントの利用可能量そのものが静的ではなく、人口減少に伴う財政制約の代理、洪水復旧負担、移転後のインフラ維持負担などにより変動する。これにより、短期的に被害を抑える対策が、将来の適応余力を削ぐ可能性も含めて学習対象となる。

時間構造は、2026–2050年、2051–2075年、2076–2100年の三ターンを基本とする。各ターン開始時に参加者は政策配分を決定し、その配分を当該 25 年間にわたり毎年適用する形で順次シミュレーションが進行する。同時に、同一気候条件のもとで政策を一切実施しないベースライン軌跡も並行計算され、年次結果にはベースラインとの差分（洪水被害差、収量差、生態系差）が明示的に付与される。この設計により、絶対値だけでなく「対策をしなかった場合と比べてどれだけ改善したか」という相対評価が可能になる。ターン終了後には、モデルから生成されたイベント（大規模洪水、生態系悪化、政策効果の発現、予算圧迫など）が提示され、その後に 25 年分の要約レポートが表示される。最終ターン終了後は総合評価画面へ遷移し、セッション全体の学習を締めくくる。

評価の中核指標は、洪水被害、農作物生産、生態系の三点である。これらは生の物理量に加え、期間ごとに定義された良い水準と悪い水準を用いて 0–100 点程度のスコアへ正規化される。洪水被害については、温暖化の進行に伴い後半ほど被害規模が大きくなりやすいことを踏まえ、2050年・2075年・2100年で異なる基準を用いる。農作物と生態系については全期間で共通の基準を用い、長期的な劣化や回復を比較しやすくしている。最終評価では、利用者結果を対策なしベースラインおよび AI 最適解ベンチマークとレーダーチャートで重ねて表示し、さらに保存された他グループ結果とのランキング比較を行うことができる。この多層比較は、単一の最適解を押し付けるのではなく、気候シナリオと価値判断のもとで多様な適応経路が存在することを示すための装置である。

## 4. ソフトウェアアーキテクチャ

### 4.1 全体構成

本アプリケーションは、表現・操作を担うフロントエンドと、状態遷移・指標計算・ログ保存を担うバックエンドに明確に分離されている。フロントエンドの `App` は、セッション状態機械として機能し、`entry`（開始設定）、`game`（政策決定）、`consequence`（イベント提示）、`report`（サイクル報告）、`ending`（最終評価）、`comparison`（他者比較）といったフェーズを遷移させる。状態の中核は `useSimulation` フックに集約されており、現在年、サイクル番号、現在状態ベクトル、履歴、政策履歴、ローディング状態、LLM コメント、住民評議会情報などが一元管理される。バックエンドへの通信は HTTP API を通じて行われ、1 年分のシミュレーション要求を 25 回繰り返すことで 1 ターンを進める。この逐次呼び出しは実装上はシンプルであるが、各年の状態依存性を保ったままフロントエンド側で履歴を蓄積できる利点がある。

フロントエンドはページコンポーネントと機能コンポーネントに分割されている。開始画面では参加者属性と気候シナリオを設定し、ゲーム画面では流域ステータス、政策決定パネル、詳細パネル、分析ビューを組み合わせる。分析ビューではシステムダイナミクス図の提示と、任意の二指標による散布図探索が可能であり、参加者は「何が起きているか」を物語的に理解するだけでなく、時系列データとして再解釈できる。イベント画面は、洪水、気候、農業、生態系、政策効果、予算などのカテゴリごとに視覚的トーンを変え、アイコン画像とともに結果を提示する。最終画面と比較画面は、スコア正規化ロジックとベンチマーク系列を共有し、セッション内の一貫した評価言語を維持する。

### 4.2 フロントエンドの主な機能モジュール

開始画面は、参加者に対して本ソフトウェアの問題設定を最初に固定する役割を持つ。利用者はユーザ名を必須入力し、任意でチーム名を設定したうえで、上流モード、下流モード、チーム（流域一体）モードのいずれかを選択する。上流モードでは植林、堤防・河川改修、田んぼダムなど供給側・流域管理側の対策が中心となり、下流モードでは住宅移転、防災訓練、農業 R&D など暴露削減や社会的適応が中心となる。チームモードでは全政策が利用可能であり、役割分担を超えた統合的な配分を試せる。気候シナリオは RCP 1.9、2.6、4.5、6.0、8.5 から選択でき、それぞれの定性的説明が UI 上に併記される。これにより、同じ政策配分でも気候外力の強さによって帰結が大きく変わることを、実験条件として明示できる。

ゲーム画面は、政策決定の主戦場である。画面上部には現在年とターン情報が示され、流域ステータス領域には洪水、農業、生態系、利用可能予算などの要約が表示される。洪水については直近 25 年累計被害を期間別基準で評価し、良好・注意・深刻といった段階表現へ変換するため、専門的な円単位の数値に不慣れな利用者でも危機感の変化を把握しやすい。政策決定パネルでは、各政策をスライダーで調整し、弱・標準・強といった強度帯に応じたプラス面・マイナス面の説明文が表示される。これは、効果の大きさだけでなく、時間遅れ、上限、副作用、他施策との補完必要性を事前に意識させるためのガイドである。利用可能ポイントを超える入力は内部で切り詰められ、見た目のスライダー範囲は維持したまま実行可能性を保証する。

背景映像は、累積的な植林投資と治水投資の水準に応じて切り替わり、抽象的な数値変化を景観的なフィードバックへ翻訳する。この演出はモデルの科学性を直接増やすものではないが、参加型セッションにおいて「流域の状態が変わりつつある」という感覚を補強し、議論の触発装置として機能する。詳細パネルや住民評議会・インタビュー機能は、数値指標では拾いきれない社会的意味づけを補う。バックエンドが生成する LLM フィードバックは、当該ターンの政策とシミュレーション行を入力として短い講評を返し、住民ペルソナとの対話は、適応政策が誰にどのように感じられるかを具体化する。これらの生成系機能は、モデル本体の決定論的・再現可能な計算とは分離されており、科学的再現性とコミュニケーション上の多様性を両立させる意図がある。

分析画面では、システム構造の静的理解とデータ探索的理解を併置する。前者は因果関係や政策効果経路を示す図版・要約であり、後者は洪水被害額、収量、生態系、政策費用、気温、降水量、極端降水頻度、利用可能水量、森林面積、堤防水準、住民防災能力、高リスク住宅数、田んぼダム面積などの指標を軸に選んで散布図を描く機能である。点の色分けは 25 年区分に対応するため、初期・中期・後期でトレードオフ構造がどう変化したかを視覚的に追跡できる。サイクル報告画面は、各ターン終了時に洪水スコア、農作物スコア、生態系スコアとその生データを要約し、前ターンとの改善・悪化を示す。イベント画面と報告画面を最終評価の前に必ず挟むことで、参加者は「最後の数字」だけを見るのではなく、経路上の重要な転換点を振り返ることができる。

### 4.3 バックエンド連携とデータフロー

1 ターンの進行時、フロントエンドは現在の状態ベクトルと政策スライダー値を用いて、対象 25 年の各年について `Sequential Decision-Making Mode` のシミュレーション要求を送る。要求にはユーザ名、シナリオ名、意思決定変数、RCP 値、および予算関連の補助状態（利用可能ポイント、人口乗数、移転ペナルティ、洪水復旧ペナルティなど）が含まれる。バックエンドは 1 年分の更新を行い、指標出力を返す。フロントエンドはその出力から次状態を抽出し、年次履歴へ追加する。並行してゼロ政策のベースラインも同様に進め、明示的な差分列を履歴へ結合する。ターン終了後は、履歴からイベントを収集・重複除去・優先度ソートし、未提示の重要イベントをキューとして表示する。最終到達時には比較用結果をサーバ側へ保存でき、他グループのスコア一覧取得と組み合わせて集合的な振り返りを可能にする。

このデータフローの特徴は、意思決定の単位（25 年）とモデル更新の単位（1 年）を分離している点にある。参加者にとっては操作回数が抑えられ、ワークショップの時間制約に適合する。一方でモデル側は年次の累積投資、森林成長の遅れ、研究効果の浸透、洪水系列の変動などを保持できる。また、フロントエンドが履歴を保持することで、分析画面や最終評価、比較画面が同一の時系列を再利用でき、説明可能性が高まる。再現性の観点では、シミュレーション乱数の固定により同一入力での軌跡比較が容易であり、生成 AI 部分のみを可変とすることで、科学的結果とコミュニケーション演出を区別して議論できる。

## 5. 利用者の意思決定フローと学習設計

本ソフトウェアの学習設計は、情報提示、意思決定、帰結の観察、振り返りという循環を三回繰り返すことにある。最初の入力画面で気候シナリオと役割を固定することで、参加者は「不確実性のどの断面を見ているのか」「どの政策レバーを握っているのか」を自覚する。ゲーム中は、流域ステータスによる現状認識、政策説明による事前学習、スライダー操作による仮説形成、25 年進行による仮説検証、イベントによる物語化、レポートによる定量的要約が連続する。特にイベント提示は、単に値が閾値を超えたことを告げるのではなく、森林効果の発現、堤防完成、移転需要の高まり、予算圧迫、生態系の危機など、因果の断片を可視化する。これにより、複合システムに特有の「意図せざる結果」や「遅れて効く投資」が議論の対象になる。

役割別モードは、ステークホルダー間の権限分断を擬似的に再現する装置でもある。上流対策のみを操作する参加者は、暴露側の脆弱性を直接下げられない制約の中で治水と緑のインフラの配分を考えねばならず、下流対策のみを操作する参加者は、外力そのものを十分に制御できない中で移転・備え・農業適応を設計することになる。チームモードでは全体最適を探索できる一方、ポイント制約のもとで何を優先するかという価値判断が前面に出る。最終比較では、自分たちの結果がベースラインより改善していても AI ベンチマークや他グループに劣る場合があり、そのギャップが「もっと早い段階で何をすべきだったか」という振り返りを誘発する。逆に、特定指標だけを極大化して総合バランスを崩す経路も可視化されるため、単一目的最適化の危険性を体験的に示せる。

本ソフトウェアは、厳密な意思決定支援システムというより、探索的で対話的な学習環境として位置づけられる。それでも、モデルに基づく一貫した因果構造、明示的な制約条件、再現可能な計算、比較可能なスコア体系を備えている点で、単なる啓発ゲームを超えた環境モデリング・ソフトウェアとしての要件を満たす。参加者は、画面上で得た洞察を、実際の流域計画における適応経路思考、オプション価値、柔軟性の維持、後悔の最小化といった概念へ接続しやすい。また、研究用途としては、異なる RCP や役割設定のもとでの人間の適応選択データを収集する実験プラットフォームとしても機能しうる。

## 6. 評価指標、ベンチマーク、比較機能

評価系は、本ソフトウェアの科学的主張と教育的主張をつなぐ要である。生指標としては洪水被害額（円）、作物収量、生態系レベルが中心であり、これに政策費用や状態変数が付随する。スコア化は、望ましい水準と望ましくない水準の間で線形に正規化され、洪水については「被害が小さいほど高得点」、収量と生態系については「値が高いほど高得点」となる。期間別に基準を変えることで、後期の気候ストレス下でも早期と同じ尺度で安易に比較してしまわないよう配慮している。サイクル報告では 25 年累計または平均を代表値として用いるため、単年のノイズに過度に左右されにくい。

ベンチマークは二種類用意されている。第一は対策なしベースラインであり、同一気候シナリオで政策を実施しなかった場合の参照軌跡である。第二は AI エージェント最適解であり、あらかじめ探索された代表的な良策配分とその帰結を示す。これらは最終画面のレーダーチャートに重ね描きされ、利用者は自分の経路がどの次元で優れ、どこで遅れているかを直観的に把握できる。さらに、セッション中に保存された他グループ結果を取得して総合スコアおよび個別スコアで順位付けする機能があり、集合研修における競争と協調のバランスを調整できる。比較画面は、勝敗を決めること自体が目的ではなく、多様な適応戦略の分布を見せることに主眼がある。

## 7. 実装上の留意点とソフトウェア品質

フロントエンドは React 19 系と Vite を用い、チャート描画に Recharts を利用する比較的軽量な構成である。状態管理は大規模な外部ライブラリに依らず、セッション寿命のカスタムフックで足りる範囲に留めている。これはワークショップ用途での起動の簡易さと、コード読解の容易さを優先した選択である。一方、25 年分の逐次 API 呼び出しは通信回数が多いため、ネットワーク遅延やサーバ負荷の影響を受けやすい。現状は教育・実験用途の同時接続規模を想定した設計であり、大規模同時アクセスや完全オフライン実行を主目的とはしていない。また、文字コードや指標名の揺れを吸収するマッピングがフロントエンド側に存在し、バックエンド出力のキー名差分に対する耐性を持たせている。

モデルと UI の一貫性を保つため、政策の最小単位・上限・説明文・イベント画像・スコア基準はデータモジュールとして分離されている。これにより、パラメータ更新時に画面文言とロジックの双方を追跡しやすくなっている。生成 AI 連携はオプション的性格が強く、サーバ側で利用できない場合でもシミュレーション本体と基本 UI は継続可能である。乱数管理については、研究上の再現性を優先してシミュレーションを固定シード化し、表現の自然さのために LLM 関連のみ可変とする方針が採られている。この分離は、論文や報告書で結果を記述する際に「どの部分が再現可能で、どの部分が演出か」を明確にするうえで重要である。

## 8. 想定利用シナリオ

第一の利用シナリオは、大学や研究機関のワークショップである。少人数グループが異なる RCP や役割でプレイし、終了後に結果比較画面を用いて討議する。ここでは、正解の暗記ではなく、なぜその配分にしたのか、どの時点で方針転換すべきだったのかを言語化することが学習成果となる。第二は、行政・市民向けの適応コミュニケーションである。専門用語を抑えつつ、洪水・農業・生態系の三軸で将来を語ることで、利害の異なる主体が同じ画面を見ながら議論できる。第三は、研究実験である。操作ログ、政策履歴、最終スコアを収集すれば、情報提示の違いや役割分担が適応選好に与える影響を分析できる。第四は、モデル開発者自身による回帰的検証である。UI を通じて極端な政策や制約条件を試し、イベント発火や予算更新の妥当性を確認できる。

いずれのシナリオでも重要なのは、本ソフトウェアが「未来を予測して示す」ことよりも、「仮定された因果構造のもとで意思決定の帰結を探索する」ことに主眼を置いている点である。気候シナリオは外部から与えられ、モデル構造も単純化を含む。そのうえで、参加者は不確実性と制約の中で優先順位をつけ、事後的にその判断を反省する。環境モデリング・ソフトウェアとしてみたとき、価値はモデルの網羅性だけでなく、モデルを社会的学習のループに載せるインタフェース設計にもある。`frontend-new` は、そのインタフェースを、流域適応という具体的ドメインに特化して実装した事例である。

## 9. 限界と今後の拡張

本ソフトウェアには、論文投稿時に明示すべき限界がある。第一に、モデルは特定の仮想流域・パラメータセットに基づく教育・探索用モデルであり、個別実流域への即時適用や詳細設計代替を意図していない。第二に、社会経済過程（人口、財政、政治的実現可能性、合意形成コストなど）は高度に抽象化されており、政策ポイントやペナルティとして代理表現される。第三に、生態系や農業の表現は主要指標への集約を伴うため、生物多様性の詳細や農家の異質性までは分解しない。第四に、LLM による講評や住民対話は、モデル出力の解釈補助であって、検証済みの社会調査代替ではない。第五に、現状の通信方式は年次逐次呼び出しであり、計算速度や堅牢性の面で改善余地がある。

今後の拡張としては、実流域データや地域統計の導入、不確実性のアンサンブル提示、適応経路（DAPP）との接続、オフライン実行や結果エクスポートの強化、アクセシビリティと多言語化の拡充、ワークショップログの研究倫理に配慮した収集機能などが考えられる。また、フロントエンドの分析機能を、単なる散布図から感度分析やシナリオ発見（例えば PRIM 的な事後解析）へ発展させれば、参加者が自分の結果を研究的問いに変換しやすくなる。さらに、役割モードをネットワーク対局型に拡張し、上流・下流の同時意思決定と外部性を明示する設計も、参加型環境モデリングとして自然な発展方向である。

## 10. 結語

River Basin Adaptation Game の `frontend-new` は、気候変動下の流域適応を、順次意思決定・複数目的評価・役割制約・イベント提示・ベンチマーク比較として実装した対話型環境モデリング・ソフトウェアである。その本質は、複雑な数値モデルを閉じた専門家ツールに留めるのではなく、参加者が仮説を立て、制約の中で選択し、時間遅れのある帰結を観察し、他者や参照解と比較して学習する循環を支える点にある。バックエンドの年次シミュレーションが科学的骨格を提供し、フロントエンドがその骨格を意思決定の物語と可視化へ変換する。Environmental Modelling & Software の読者にとって本ソフトウェアは、モデルと社会的学習をつなぐソフトウェア設計の具体例として、また教育・ワークショップ・探索的政策分析のための再現可能な実装として位置づけられる。今後は実流域への適合、不確実性コミュニケーションの強化、研究データ収集基盤としての整備を進めることで、環境モデリングコミュニティにおける参加型ソフトウェアの実践知をさらに積み重ねることが期待される。

## 付記：ソフトウェア構成の要約（参考）

本稿本文は段落記述を優先したが、再現性確保のため主要構成要素をここに簡潔に対応づける。利用者インタフェースは `frontend-new`（Vite + React）にあり、開始設定、政策決定、イベント、サイクル報告、最終評価、グループ比較の各画面を含む。セッション状態と 25 年進行制御は `useSimulation` が担い、政策定義・予算制約・スコア正規化・指標表示はそれぞれ独立したデータモジュールに分離されている。計算エンジンは `backend` の年次シミュレーションと FastAPI エンドポイントであり、RCP 別気候パラメータ、政策単位変換、状態更新、イベント生成、比較結果保存、任意の LLM 連携を提供する。対象期間は 2026–2100 年、意思決定は約 25 年ごとの三サイクル、評価の基本軸は洪水被害・農作物生産・生態系である。
